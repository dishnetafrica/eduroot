# Module: Fee Pipeline

End-to-end walkthrough of how a fee goes from configuration to collection to receipt. Read this before touching any fee-related code.

---

## Overview

```
Admin configures fees (once per session)
  ↓
Fees are assigned to students (at enrollment / session start)
  ↓
Student / parent pays (online or offline)
  ↓
Accountant records / confirms payment
  ↓
Receipt generated and sent (PDF + WhatsApp + email)
```

---

## Phase 1 — Configuration (Admin, start of session)

### Step 1: Define fee types
`Admin → Fees → Fee Types` → writes to `feetype`

Examples: Tuition Fee, Lab Fee, Library Fee, Sports Fee

### Step 2: Create fee groups
`Admin → Fees → Fee Groups` → writes to `fee_groups` + `fee_groups_feetype`

A fee group bundles multiple fee types with amounts and due dates:
```
"Monthly Fee Pack"
  ├── Tuition Fee   ₹2,000  due: 10th of month
  ├── Library Fee   ₹200    due: 10th of month
  └── Sports Fee    ₹150    due: 10th of month
```

### Step 3: Assign fee groups to classes
`Admin → Fees → Assign Fee Groups` → writes to `fee_session_groups`

```sql
INSERT INTO fee_session_groups (fee_group_id, class_section_id, session_id, due_date)
VALUES (1, 5, 3, '2024-04-10');
```

This is the "publish fees" action. From this point, all students in that class section owe this fee group for this session.

### Step 4: Define discounts (optional)
`Admin → Fees → Discounts` → writes to `fees_discounts`

---

## Phase 2 — Student Assignment (at enrollment)

When a student is enrolled (`student_session` row created), `student_fees_master` rows are auto-generated for all `fee_session_groups` assigned to their class section.

**Code location:** `Studentfee.php` or the model triggered during `Student.php::add()`

```sql
-- One row per fee_session_group the class has
INSERT INTO student_fees_master (student_session_id, fee_session_group_id, amount)
SELECT ss.id, fsg.id, fg.total_amount
FROM student_session ss
JOIN fee_session_groups fsg ON fsg.class_section_id = ss.class_section_id
JOIN fee_groups fg ON fg.id = fsg.fee_group_id
WHERE ss.id = {new_student_session_id};
```

`is_system = 1` on auto-generated rows. Manual fee additions have `is_system = 0`.

## Phase 3 — Payment collection

### Offline (cash / cheque)

1. Accountant opens `Admin → Student Fees → Collect Fee`
2. Selects student → sees all `student_fees_master` rows with balance
3. Enters amount, payment mode, date
4. On submit:
   - Inserts into `student_fees` (payment header)
   - Inserts into `student_fees_deposite` (line items per fee type paid)
   - Updates balance calculation
   - Generates receipt number from `fee_receipt_no` sequence
   - Triggers `fee_submission` notification event

### Online (student portal)

1. Student opens `Student Portal → Pay Fees`
2. Sees outstanding `student_fees_master` rows
3. Clicks "Pay Online" → redirected to gateway
4. Gateway controller:
   - Creates `student_fees_processing` row (status = `pending`)
   - Redirects to gateway
5. On callback / webhook:
   - Updates `student_fees_processing` (status = `success` or `failed`)
   - If success: inserts `student_fees` + `student_fees_deposite`
   - Inserts raw response into `gateway_ins_response`
   - Triggers `fee_processing` notification event

**Important:** Never rely on the redirect return URL alone to confirm payment. Always verify via the webhook/callback and check `gateway_ins_response` before marking a payment as complete.

## Phase 4 — Receipt generation

Receipt PDF is generated by:
```php
// In Studentfee.php or Report.php
$this->load->library('pdf_library');
$this->pdf_library->generate_fee_receipt($student_fees_id);
```

The PDF uses:
- `print_headerfooter` — school letterhead
- `student_fees` + `student_fees_deposite` — payment details
- `students` + `student_session` + `classes` + `sections` — student details
- `fee_receipt_no` — receipt number

The receipt number is assigned atomically:
```sql
-- Inside a transaction:
SELECT receipt_no FROM fee_receipt_no WHERE id = 1 FOR UPDATE;
UPDATE fee_receipt_no SET receipt_no = receipt_no + 1 WHERE id = 1;
-- Use the fetched value as the receipt number
```

---

## Phase 5 — Notifications

After a payment is recorded, the notification pipeline fires:

1. **Email** → `email_template` for `fee_submission` event → sent via PHPMailer with receipt PDF attached
2. **SMS** → `sms_template` for `fee_submission` → sent via configured SMS gateway
3. **WhatsApp** → if `sch_settings.whatsapp_api_*` is configured → sends to `students.guardian_phone`
4. **Push** → if `students.parent_app_key` is set → sent via Firebase FCM

Each channel is independently toggled in `notification_setting`.

## Fee balance calculation

There is no single "balance" column. Balance is always computed:

```sql
SELECT 
  sfm.amount AS total_owed,
  COALESCE(SUM(sf.amount - sf.amount_discount + sf.amount_fine), 0) AS total_paid,
  sfm.amount - COALESCE(SUM(sf.amount - sf.amount_discount + sf.amount_fine), 0) AS balance
FROM student_fees_master sfm
LEFT JOIN student_fees sf ON sf.feemaster_id = sfm.id
WHERE sfm.student_session_id = {student_session_id}
GROUP BY sfm.id;
```

Do not cache this in the database — always compute fresh from transactions.

---

## Transport fees

Transport fees follow the same structure but use separate tables:
- `transport_feemaster` (instead of `feemasters`)
- `student_transport_fees` (instead of `student_fees`)
- `student_vehicle_months` (monthly tracking)

The collection screen is separate but the logic is identical.

## Common mistakes

| Mistake | Consequence |
|---|---|
| Not scoping to `session_id` | Returns fees from all years |
| Reading balance from a cached column | Stale after a payment/discount |
| Not inserting `student_fees_deposite` | Receipt line items missing, reports wrong |
| Trusting gateway redirect return URL | Missed payments, double payments |
| Not locking `fee_receipt_no` row | Duplicate receipt numbers under concurrent load |
